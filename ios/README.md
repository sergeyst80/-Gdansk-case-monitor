# Gdańsk Case Monitor for iOS

Нативный проект для iPhone и iPad на iOS 17.0+. Первая iOS-версия: 1.0.0.
Подготовлен на основе Android-приложения, включая применимые меры безопасности
версии 1.2.1, с учётом отличий и ограничений iOS. Подготовка обновлена 3 октября 2026 года.

## Что подготовлено

- SwiftUI: адаптивные карточки, системное меню, светлая и тёмная темы,
  поддержка размера текста и направления справа налево.
- Несколько пользователей, добавление и редактирование через меню Users,
  удаление свайпом или контекстным меню с подтверждением.
- Ручная проверка пользователя и всех пользователей последовательно.
- Настройки языка, автообновления, интервала и перевода.
- 12 языков интерфейса; по умолчанию английский.
- Нижняя строка текущего действия: подключение, загрузка, вход, чтение,
  сохранение, подготовка моделей, перевод и бездействие.
- Сведения и пароли в локальном Keychain с доступом после первого
  разблокирования и без синхронизации iCloud.
- WKWebView с отдельным непостоянным хранилищем cookies для каждого входа.
- Локальный перевод Google ML Kit, оригинал доступен отдельной кнопкой.
- Фоновые проверки через BGAppRefreshTask и уведомления об изменении.
- Иконка, shared Xcode scheme, privacy manifest и XCTest-тесты.

Проект находится в папке `ios/` репозитория `sergeyst80/-Gdansk-case-monitor`.
Это независимое приложение; Android-сборка и существующий APK не менялись.

## Важное ограничение результата

Проект подготовлен на Linux. Здесь нет macOS, Xcode или iOS SDK:
**Swift-код не компилировался, XCTest не запускался, IPA не создан и
приложение не проверено на iPhone**. Структурная проверка файлов не заменяет
сборку и тестирование. Перед использованием нужен проход проверки на Mac.

## Сборка на Mac

### Необходимые инструменты

| Инструмент | Для чего нужен |
| --- | --- |
| Mac с macOS, совместимой с выбранным Xcode | Полная сборка iOS; Linux и Windows не заменяют macOS с iOS SDK. Apple Silicon рекомендуется, но сам по себе не является требованием проекта. |
| Полный Xcode с iOS SDK | Swift-компилятор, редактор проекта, `xcodebuild`, подпись и Organizer. Одного пакета Command Line Tools недостаточно. |
| iOS Simulator и установленный runtime iOS 17 или новее | Запуск и тесты без физического iPhone; runtime установите через настройки Xcode. |
| Git | Клонирование и обновление репозитория. |
| CocoaPods (`pod`) | Установка зависимости `GoogleMLKit/Translate` версии `8.0.0`, указанной в Podfile, и создание `.xcworkspace`. |
| Python 3 (`python3`) | Структурные проверки `tools/validate_project.py`; не требуется самому приложению. |
| Terminal и Bash | Запуск команд и `tools/build_macos.sh`. |
| Интернет | Загрузка Xcode, runtime и Pods; подключение к порталу при проверке приложения. |

Выберите Xcode с поддержкой iOS 17+ и версии iOS вашего тестового устройства.
Совместимые версии macOS, SDK и устройств проверяйте по
[таблице Apple](https://developer.apple.com/xcode/system-requirements/).
Конкретная версия Xcode для этого проекта пока не подтверждена сборкой.
Swift и XCTest входят в Xcode: отдельно устанавливать их не нужно.
Android SDK, Java, Gradle и Android-ключ подписи для этой сборки не нужны.

### Установка и проверка инструментов

1. Установите полный [Xcode](https://developer.apple.com/xcode/), откройте его,
   примите лицензию и дождитесь установки дополнительных компонентов.
2. Установите iOS Simulator runtime в настройках Xcode. В зависимости от
   версии Xcode раздел называется Platforms или Components.
3. Если установлен [Homebrew](https://brew.sh/), установите дополнительные
   инструменты следующей командой. Homebrew — удобный, но необязательный
   способ установки; альтернативный способ CocoaPods описан в
   [официальном руководстве](https://guides.cocoapods.org/using/getting-started.html).

   ```bash
   brew install cocoapods python
   ```

4. Проверьте окружение:

   ```bash
   xcode-select -p
   xcodebuild -version
   xcrun --sdk iphoneos --show-sdk-version
   xcrun simctl list devices available
   git --version
   pod --version
   python3 --version
   ```

   Если `xcode-select -p` показывает `/Library/Developer/CommandLineTools`
   вместо полного Xcode, выберите установленный Xcode. Команда ниже подходит
   для стандартного расположения; при другом пути измените его:

   ```bash
   sudo xcode-select --switch /Applications/Xcode.app/Contents/Developer
   ```

### Учётная запись и физический iPhone

- Для сборки и тестов в симуляторе подпись и платная подписка Apple Developer
  Program не требуются.
- Для запуска на собственном iPhone нужны Apple Account в Xcode, команда
  подписи, iPhone с iOS 17+, сопряжение с Mac и включённый Developer Mode.
  Для первого подключения удобно использовать USB-кабель.
- Бесплатная Personal Team позволяет тестировать на своих устройствах,
  но имеет ограничения подписи и возможностей. Для TestFlight, App Store
  и распространения через Ad Hoc требуется Apple Developer Program.
  Различия описаны в [руководстве Apple](https://developer.apple.com/support/compare-memberships/).
- Секреты подписи храните локально в Xcode/Keychain. Не добавляйте пароли,
  приватные ключи или provisioning profiles в репозиторий.

### Открытие проекта и сборка

1. Клонируйте репозиторий на Mac и перейдите в `ios/`. Не копируйте
   `.secrets` Android-проекта: они не нужны для iOS.
2. В Terminal перейдите в эту папку и выполните:

   ```bash
   pod install
   open GdanskCaseMonitor.xcworkspace
   ```

3. Открывайте именно `.xcworkspace`, созданный CocoaPods, не только
   `.xcodeproj`: приложение импортирует MLKitTranslate.
4. Выберите scheme **GdanskCaseMonitor** и iPhone Simulator.
5. Выполните **Product → Build**, затем **Product → Test**.
6. Устраните диагностику Xcode, если она появится; этот этап ещё не выполнен.

Для сборки без подписи в симуляторе предусмотрен скрипт:

```bash
bash tools/build_macos.sh
```

Он устанавливает Pods и вызывает xcodebuild для симулятора. На Linux
скрипт сообщает об отсутствии подходящей платформы и не создаёт IPA.

Варианты команд из папки `ios/`:

```bash
bash tools/build_macos.sh simulator
SIMULATOR_ID=YOUR_SIMULATOR_UUID bash tools/build_macos.sh test
bash tools/build_macos.sh device YOUR_APPLE_TEAM_ID
bash tools/build_macos.sh archive YOUR_APPLE_TEAM_ID
```

Подставьте реальный UUID из `xcrun simctl list devices available` и 10-символьный
Team ID из вашей команды Apple. Для `device` и `archive` сначала войдите в
Xcode → Settings → Accounts. Apple ID, пароль, сертификаты и профили не
включены в проект. Архив создаётся в `build/GdanskCaseMonitor.xcarchive`;
экспорт IPA и способ распространения выбираются отдельно в Organizer.

В GitHub → Actions доступен ручной workflow **Check iPhone project
(unsigned simulator)**: Run workflow. Он проверяет структуру, собирает
симулятор и запускает XCTest на macOS без ключей подписи. Workflow ещё не
запускался; его наличие не означает успешной компиляции.

### Установка на iPhone и выпуск

На iOS не переносится Android FLAG_SECURE: блокировка скриншотов этим
механизмом отсутствует. Не показывайте персональные данные при записи или
демонстрации экрана; для снимков вручную скрывайте имя, логин и номер дела.
Непостоянное хранилище WKWebView изолирует аккаунты без переноса cookies
между входами. Ошибка Keychain блокирует перезапись, а перед каждым
сохранением проверяется читаемость существующей записи.

В **Signing & Capabilities** выберите свою команду Apple, задайте уникальный
Bundle Identifier при необходимости и оставьте автоматическую подпись.
Для физического устройства и распространения нужен соответствующий
профиль подписи. Не передавайте Apple ID, пароль или приватные ключи в чат.

Идентификатор фоновой задачи `pl.sergeyst.gdanskmonitor.ios.refresh` должен
совпадать в Info.plist и BackgroundScheduler.swift. При его переименовании
меняйте оба места. Включён background mode **Background fetch**.

После успешной сборки и проверки на iPhone используйте **Product → Archive**
и Organizer для выбранного способа распространения. Android-ключ подписи
не используется для iOS. Готового installable IPA сейчас нет.

## Краткое руководство

1. Откройте меню в правом верхнем углу → **Users** → **+**.
2. Введите локальное имя, настоящий логин портала и пароль → **Save**.
3. На главном экране нажмите **Refresh all** и дождитесь результата.
4. Для редактирования нажмите пользователя в Users. Пустое поле нового
   пароля сохраняет существующий пароль.
5. Для удаления смахните строку пользователя или удерживайте её,
   выберите Delete и подтвердите. Дело на портале не удаляется.
6. В меню → **Settings** выберите Language, интервал, Auto-refresh
   и при необходимости Translate portal text. Настройки сохраняются сразу.
7. После успешного перевода используйте Show original / Show translation.

На первом запуске разрешите уведомления. Они сообщают только о факте изменения,
без имени и текста дела. Подробности доступны в приложении.
При неуспешной проверке старые сведения остаются: проверяйте время последнего
успешного запроса и текст ошибки. Завершение запроса не означает успех.

### Автообновление на iOS

Периоды: 15, 30, 60, 180, 360, 720 и 1440 минут. Пока главный экран активен,
приложение проверяет наступление периода примерно каждые 30 секунд.
Фоновая работа — **best effort**: earliestBeginDate не гарантирует запуска
в указанное время, iOS определяет момент и доступную длительность работы.
После принудительного закрытия или при ограничениях фоновой активности
проверки могут не выполняться. Для важных ручных проверок держите приложение
открытым. Выключение Auto-refresh отменяет будущие фоновые задачи, но
уже выполняющийся запрос может завершиться.

Много пользователей или медленный JavaScript-портал могут не уложиться
в выделенное системой время. При expiration задача отменяется без принятия
неполного результата за успешный. После повторного открытия выполните
ручную проверку. Для гарантированного круглосуточного мониторинга нужен
отдельный сервер, которого в этой версии нет.

Первый успешный фоновый запрос создаёт исходный результат. Уведомление
появляется только при изменении относительно уже сохранённых данных.
Перевод отображается на карточках, а не в тексте фоновых уведомлений.

### Перевод и конфиденциальность

Перевод выключен по умолчанию. Google ML Kit переводит этап, описание,
примечания и текст документов на устройстве. Отдельные поля имени, номера
дела, даты и пароли не передаются переводчику. Данные внутри свободного
текста могут обрабатываться. Модели загружаются по Wi-Fi; SDK может обмениваться
служебными данными с Google. Это не облачный Google Translate API.
Для определения языка применяется Apple NaturalLanguage; при неизвестном
языке короткого текста предполагается польский.

Перевод последовательный, чтобы ограничить расход памяти. Оригинальные
сведения и контроль изменений не заменяются переводом. Кэш результата
хранится только в памяти, а загруженные языковые модели — на устройстве.
При ошибке показывается оригинал; повторите обновление или выключите
и включите перевод. Машинный перевод может ошибаться.

Аккаунты и результаты не экспортируются и не импортируются из Android.
Keychain имеет собственный жизненный цикл: после удаления и повторной
установки записи **могут сохраниться**. Для удаления конкретных сохранённых
аккаунтов используйте Users → Delete перед удалением приложения.
После изменения команды подписи или устройства доступ к прежним данным
не гарантируется. Ошибка доступа к Keychain не вызывает автоматической
очистки: разблокируйте устройство и откройте приложение повторно.

### Сеть и сертификаты

Используется тот же адаптер портала, что в Android. Данные входа отправляются
только на `https://klient.gdansk.uw.gov.pl/`; HTTP и сторонние перенаправления
включая подфреймы отклоняются. Публичные content rules WebKit ограничивают
подресурсы точным хостом портала по HTTPS/WSS и портом 443. Это не замена
серверной CSP и не гарантия перехвата всех видов трафика; проверьте на iPhone,
что фильтр не мешает загрузке Vaadin. CAPTCHA/MFA не обходятся. Вход в обычном браузере
не импортирует сессию в приложение.

Для неверной цепочки портала включён тот же проверенный публичный Certum CA.
Он применяется только для точного домена портала с системными корнями,
SSL-политикой имени хоста и обязательным SecTrustEvaluateWithError.
Неуспешная проверка доверия отменяет соединение; trust-all и ATS exceptions
не используются. Происхождение CA: Resources/certum_ca_provenance.md.
Поведение этой цепочки на реальном iOS необходимо проверить отдельно.

## Проверки

На Linux:

```bash
python3 tools/validate_project.py
```

Проверяются 12 локализаций и форматные аргументы, ключи текста, plist,
ресурсы Xcode, схема, иконка, идентичность JS и CA Android-версии,
заявленная политика Keychain и проверки TLS. Это девять структурных тестов,
не доказательство работоспособности Swift-кода или сетевого входа на iOS.

На Mac после установки Pods:

```bash
xcodebuild -workspace GdanskCaseMonitor.xcworkspace \
  -scheme GdanskCaseMonitor -showdestinations
xcodebuild -workspace GdanskCaseMonitor.xcworkspace \
  -scheme GdanskCaseMonitor -destination 'platform=iOS Simulator,id=YOUR_SIMULATOR_UDID' test
```

Подставьте реальный UDID из списка. XCTest проверяет начальные настройки,
интервалы, маскирование логина, схему JSON, разрешённый домен,
исключение идентификационных полей из перевода и хеширование оригинала.

До выпуска проверьте на iPhone: вход на портал, два аккаунта без смешивания
cookies, неверный пароль, CAPTCHA, сеть и TLS, все языки и RTL, изменение
настроек, загрузку моделей по Wi-Fi, отмену перевода, фоновые expiration,
уведомления и хранение данных после перезапуска.

PrivacyInfo.xcprivacy содержит декларацию UserDefaults для собственных
настроек. Перед App Store выпуском проверьте итоговый Privacy Report,
privacy manifests зависимости Google и декларации App Store Connect;
шаблон не заменяет эту проверку.
